# Observatory v1.6.0

This build combines the travel and interface foundation, the Wound opening repair and the traversal performance pass. A completely rewritten illustrated README introduces the current app through nineteen new 4K photographs and three screenshots of the interface in use. The v1.5 gallery remains archived with its original image bytes and scenes.

## What changes

- **Explore, Journey, World and Capture:** four panels, one persistent clock, semantic location names, a visible Return action, keyboard tab navigation and recoverable Quiet view.
- **Prepared travel:** submitted destinations remain distinct from the browsing draft; arrivals commit after preparation, Cancel and Retry refer to the submitted trip, and failed Return preserves its history entry.
- **Places that persist:** anchored geographic and moving-Shade marks, named viewpoints, scene import/export, and up to 24 committed previous visits across reloads. Reopening pauses playback.
- **Wound continuity:** no detached terrain slabs or collision floors inside the opening; empty chunks avoid generating terrain that would be discarded.
- **Smoother traversal:** corrected preview cadence, stable terrain reservations at chunk boundaries, reused asset and lighting calculations, conservative colour-pass culling, reduced shadow-setup synchronization and cheaper station predicates.
- **Capture provenance:** actual photograph and panorama packages retain place identity, build information, world state and rendering settings. Preparation supports cancellation; successful capture restores playback.
- **Fresh presentation:** every gallery photograph is freshly framed and rendered from this build, with portable scenes and repeated-frame checks. The interface screenshots follow actual journeys through visible controls.

## Measured performance

The preceding [performance evaluation](../Observatory-Performance-2026-09-15.md) tested the integrated rendering code on Chrome / ANGLE D3D11 / RTX 5080. The publication changes add version labels, documentation and captures; rendering quality defaults and the optimized algorithms are retained.

All ten biome walks, six Wound runs and eight unattached Shade approaches measured 59.8–60.1 preview draws/s in the 1600 × 900 window. Mycelium Sea improved from 44.1 to 59.9. In a fixed-resolution 4K window, the Wound route improved from 47.7 to 55.1 and the heavy inner Shade view from 40.4 to 46.8. Adaptive preview reached approximately 60 after settling by reducing the internal raster.

The 4K-window scene raster was 3504 × 2094, with the controls occupying the rest of the window. These are warm draw rates on one machine, not display-latency measurements or a guarantee on other hardware. Fixed-resolution close views remain GPU-limited, and cold shader preparation remains expensive.

## Run and explore

Download the current repository ZIP, extract it and install Node.js 20 or later. Open **Launch Observatory.cmd** on Windows, or run `npm start`, then visit [localhost:8766](http://127.0.0.1:8766/). Use a hardware-accelerated WebGL 2 browser. There is no runtime package installation or application compilation step.

Start with **Explore → Biomes → Dark Age Forest → On foot**. Journey keeps the places visited; World holds conditions and rendering quality; Capture saves the photograph and its scene. [The full README](../../README.md) and [new gallery](../../examples/observatory/README.md) provide the illustrated guide.

## Remaining limits

Strict cold-capture repeatability is still an open diagnostic. Prepared gallery equality does not close that gate. Connected polar environments, detailed receiving-lake shore architecture, walking across both Shade faces, full climate/physical transport and broader hardware certification remain future work. The historical [integration notes](../Integration-2026-09-15.md) distinguish the implemented foundation from the larger plan.
