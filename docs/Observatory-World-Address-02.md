IB-010 implementation record · 19 September 2026

This is the address and compatibility contract for the Infinite Biomes
programme. It is intentionally separate from terrain residency: a render
origin, camera path, request order, worker count or cache eviction cannot alter
an address.

## Review result

The v1.6 runtime currently has three related but different identities:

| Existing value | Meaning | v2 treatment |
|---|---|---|
| `packAddress` schema 1 | Watershed pack, geography/art revision, seed and province anchor | Migrated as explicit legacy provenance; no old scene is rewritten implicitly |
| `provinceAnchor` / `siteAnchor` | Saved shell direction for a province or local field site | Encoded as a canonical cube-sphere face, cell and local coordinate |
| `terrainAnchor` | Temporary camera-relative walking frame | Remains a render-frame concern; it is not accepted as geographic identity |

The current ground cache key is deliberately unchanged by this item. The
address module and fixtures land first; cache-key and worker-packet migration
belongs to IB-030 after topology work has passed.

## Canonical schema

Every address has these fields in this order:

```json
{
  "schema": 2,
  "worldSeed": 713,
  "geographyRevision": 1,
  "terrainRevision": 2,
  "artRevision": 2,
  "assetRevision": 1,
  "heroRevision": null,
  "space": "shell",
  "face": 0,
  "level": 4,
  "x": 8,
  "y": 7,
  "local": [0.25, 0.75]
}
```

`face` is one of `+x, -x, +y, -y, +z, -z` in the implementation's fixed
orientation table. `level` is the subdivision level; a level `L` face has
`2^L × 2^L` cells. `x` and `y` are integer cell coordinates. `local` is the
canonical fractional position inside that cell, inclusive at a final edge
only when the canonical face owns that edge.

The cube projection is gnomonic and unit-vector based. Ties at exact edges or
corners are owned by the first matching signed axis in the fixed face order.
This makes face joins and poles serializable without longitude wrapping.

Shade addresses use the same metadata and surface grid, plus a stable
`shadeId` and a `parent` shell address. The parent identifies the moving Shade
and its parent-local frame; the surface `face`, cell and local coordinates
identify the place on that Shade face.

## Revisions and feature IDs

`worldSeed`, `geographyRevision`, `terrainRevision`, `artRevision`,
`assetRevision` and nullable `heroRevision` are all part of identity. A
generator or asset revision therefore cannot silently reinterpret an old
address. Feature IDs are namespaced by `waterway`, `route`, `district`,
`vegetation`, `landmark` or `hero` and include the world seed, geography
revision, canonical cell and a caller-owned local discriminator.

## Schema-1 migration

The existing Watershed address
`{schema:1,packId,geographyRevision,artRevision,seed,anchor}` migrates to a
schema-2 shell address at a declared subdivision level (level 12 by default).
The original address is retained as `legacyPack` provenance so it can be
exported byte-for-byte as a schema-1 semantic record. Its seed, geography
revision, art revision and anchor are not inferred from the camera or current
asset readiness. Historical scenes continue to load through the existing
world/session validators and do not opt into the new pack merely because this
module is present.
