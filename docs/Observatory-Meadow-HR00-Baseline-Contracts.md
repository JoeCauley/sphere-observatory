## Independent revision axes

[vegetation-revisions.js](../vegetation-revisions.js) exposes revision descriptors
and identity keys. [math.js](../math.js) owns saved-state validation so browser
workers and standalone classic-script users retain a self-contained validator.
The ordinary bootstrap loads the descriptor module after Math. H1 needs no
harness adapter or successor fixture for this step.

| Axis | Representation and validation | Change rule |
|---|---|---|
| Plant content | Descriptor `content`: provider/coverage, Meadow schema/representation/placement/ecology/appearance/canopy/material, seed/anchor/density/quality, world/geography/terrain/art/assets/Hero/support and physical chart frame | Content changes invalidate prepared content; canonical roots remain governed by the original placement contract |
| Resource layout | `residentResourceRevision`, currently 1 | Reserve revision 2 for an implemented persistent-storage backend; reject it until supported |
| Worker packet encoding | `packetRevision`, currently 1 | Legacy untagged `kind: meadow-cell-v2` is packet contract 1; `v2` names placement, not the packet revision. HR-01 defines the successor envelope and admission |
| Submission selection | `selectionRevision`, currently 1 | Compact-reference selection gets its own implemented revision; changed overlap rank/representation additionally requires a versioned appearance contract and repeated F/G review |
| Request lifetime | Runtime `requestGeneration`, nonnegative safe integer | Cancellation/request freshness; never geographic content or portable scene identity |
| Slot lifetime | Runtime `slotGeneration`, positive safe integer | Allocation reuse freshness; never a canonical root/child identifier |
| Render lifetime | Runtime `renderFrame`, nonnegative safe integer | Timing/reference-list validity; never a content revision |

Optional saved Meadow metadata uses `residentResourceRevision`, `packetRevision`
and `selectionRevision`. If absent, old saved-state output stays unchanged.
If any is supplied, validate a fixed-chart versioned profile and normalize all
three to the supported tuple `(1,1,1)`. Explicit null, strings, fractional,
negative, zero or unsupported versions fail; do not silently select a backend.
The tuple survives portable and local-session round trips. Request, slot and
render lifetimes in a saved Meadow block are rejected.

Descriptors exclude camera position, selection, timeline phase, request/slot
generations and render frames from content identity. Resource keys combine
content and the revision tuple. These descriptor keys are not a payload hash,
plant identifier or packet-admission proof. HR-01 must bind revisions and
content hashes to the actual packet, scene, reservation and slot before activation.
HR-01 will implement reservation and stale-packet admission checks.

Storage-only redesign may retain the F2 appearance envelope with a new resource
and packet revision. Geometry, overlap rank or representation changes require
their own explicit version and repeated F/G evidence. Lower density or changed
visual targets require a versioned preset and review. Existing fixture JSON,
limits, poses, lens, resolution and settings remain immutable. Any later
compatible harness adapter must preserve H1 and prove that mapping explicitly.

## Frozen measurement meanings

H1 remains the authority for the fixed 1920 × 1080, 80° / 60 fps matched off/on
protocol and every limit. Limits apply collectively across active providers.
Future instrumentation may add fields, not reduce the meaning of these counters.

| Measure | Required meaning |
|---|---|
| Resident detailed records | Count retained physical detailed populations across active, pending, received, staging and replacement lifetimes. Report unique plants, duplicate populations, allocated slots and reserved capacity separately. CPU/GPU correspondence is recorded without hiding extra populations; reference aliases do not manufacture a second population |
| Submitted detailed records | Every detailed instance in an actual production draw, including repeat submissions. Zero opacity, shader discard, clipping or zero visible pixels do not remove a submitted instance. Report clumps/coarse records separately |
| Vegetation draws | Actual vegetation subdraws across active providers and production passes. Batching must reduce real draws. A multi-draw wrapper does not erase its underlying subdraws |
| GPU bytes | Physical allocated capacity: record arenas, padding/unused slots, references, prototypes, indices/VAOs as attributable, descriptor textures/mips, staging and simultaneous replacement allocations. No credit for unused or transparent data |
| CPU bytes | Distinct backing allocations plus retained objects/metadata, queue snapshots, transferred/received packets, scratch and every worker. Aliased views count their backing allocation once within an owner; copies count separately. CPU and GPU copies each count toward their own budgets |
| Preparation | Complete main-thread request, selection/reference construction, allocation/resource/VAO/upload work and asynchronous packet reception since the preceding frame. Preserve attribution to source frame IDs and avoid double-counting overlapping intervals. Worker generation and queue-to-completion latency are reported separately, never substituted for main-thread preparation |
| Upload bytes | Actual instance/prototype/reference/descriptor updates and staging transfers per frame. Stationary animated instance/prototype uploads must remain zero; stationary selection references should be reused |
| GPU/CPU incremental time | Nonnegative differences between exactly matched off/on indexed poses. Completed GPU queries are consumed once; disjoint or unavailable results stay invalid/incomplete. Draw cadence does not establish OS presentation |
